# F-24. VIP 등급 기반 상품 노출 제어 + 트리거/기간한정 시스템

> 소스 발췌: `src/` — 1개 파일

**구간** Phase 2 (2026.02.01 ~ 02.21) | **포지션** 서버 | **AI** 협업

- **문제**: 상품을 전 유저에게 동일하게 노출하면 (1) 무과금 유저에게 고액 패키지가 계속 보여 이탈을 유발하고, (2) 고과금 유저에게 소액 상품만 보여 기회를 놓친다. 또한 "N층 클리어 시 등장", "3일간만 판매" 같은 조건부 상품을 상품마다 개별 구현하면 관리가 불가능하다.
- **해결**: 상품 시스템에 **노출 제어 축을 3개** 넣었다.
  - **VIP 등급** — 과금 수준별로 노출 상품군을 분기
  - **트리거(`TriggerAchieveItem`)** — 업적/진행 조건 달성 시 상품 등장
  - **기간한정(`LimitTime`)** — 노출 기간 제한
  이 세 축이 상품 데이터의 속성이므로, 새 조건부 상품은 **코드 없이 데이터로** 만들어진다.
- **기술**: VIP 레벨 산정, 업적 트리거 연동, 기간 한정 조건, 상품 데이터 스키마 확장
- **정량**: 구현 계획 문서 3종 / 포트폴리오 8차 설계에 반영
- **근거**:

  - `Docs/상품/완료플랜/26.02.01_상품-포트폴리오-8차-과금-수준별-노출-시스템-설계.md`
  - `Docs/상품/완료플랜/26.02.21_VIP-Level-시스템-구현-플랜.md`

- **면접 포인트**: **BM을 코드가 아니라 데이터로 표현했다.** 상품 기획이 바뀔 때마다 서버 배포가 필요하면 BM 실험 자체가 불가능하다. 3개 축을 데이터 속성으로 넣어두면 기획 변경이 데이터 변경이 된다. 상품 포트폴리오가 24차까지 개정된 기록(`Docs/상품/포트폴리오/`)이 이 유연성의 실제 필요성을 증명한다.
