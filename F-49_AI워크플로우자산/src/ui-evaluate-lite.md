# UI Evaluate Lite Skill (UXML 전용)

UI Builder에서 더미 데이터로 작업 중인 **UXML 디자인 프리뷰**를 빠르게 평가하기 위한 경량 스킬.
Play Mode 진입 없이, 본인이 UI Builder에서 보는 화면 그대로 캡처해서 평가한다.

> **언제 쓰는가**
> - UI Builder에서 UXML/USS 디자인 작업 중 즉시 피드백이 필요할 때
> - .design-preview 더미 데이터로 충분한 정적 디자인 평가
> - 동적 데이터/실제 그리드 채워짐 검증이 필요하면 → `ui-evaluate-runtime`

## 사용법

```
/ui-evaluate-lite <캡처PNG경로>
```

또는 캡처가 아직 없으면:

```
/ui-evaluate-lite <UXML경로>
```

후자의 경우 Step 1이 UXML 경로로 **자동 캡처**한다 (UI Builder를 열 필요 없음).

---

## 워크플로우

### Step 1: 캡처 (자동, headless)

UXML 경로만 주면 `UxmlDesignPreviewCapture`가 design-preview를 headless로 캡처한다 — **UI Builder를 열거나 [캡처] 버튼을 누를 필요가 없다.** `execute_code`(MCP)로 단일 동기 호출:

```csharp
var ts = System.DateTime.Now.ToString("yyyyMMdd_HHmmss");
var outPng = $"Assets/Editor/UIAutomation/Data/Screenshot/Evaluate/UXML/{UXML이름}_{ts}.png";
bool ok = PX.Editor.UIAutomation.UxmlDesignPreviewCapture.Capture("{UXML경로}", outPng);
return $"{ok}:{outPng}"; // 반환된 경로를 evaluator에게 전달
```

- **반환 시점에 PNG가 디스크에 존재**한다(delayCall/폴링 없음). 다음 Step에서 그 경로를 그대로 Read.
- 1920×1080 풀 렌더, `.design-preview` 더미 데이터 표시 상태 그대로. 폰트/그라데이션/커스텀요소(`TKGradient`·`TKBoxShadow`)/색상 충실(기존 수동 [캡처] 대비 동등 이상, 에디터 크롬 없음).
- 저장 경로/포맷은 기존과 동일(`.../UXML/{UXML이름}_{타임스탬프}.png`) — 후속 Step·Before/After 재평가가 그대로 호환.
- 이미 캡처 PNG가 있으면(`/ui-evaluate-lite <PNG경로>`) 이 Step을 건너뛴다.

> 구 방식(`PX Editor > UI Toolkit > Design Preview` 창의 [캡처] 버튼)은 UI Builder 창이 열려 있어야 하는 화면 스크래핑이라 무인 평가에 부적합 — 폴백으로만 사용.

### Step 2: UXML/USS 정적 분석

캡처된 PNG와 함께 evaluator agent에게 전달할 데이터:

1. **UXML 파일 직접 읽기** (Read 도구) — 트리 구조, name 속성, class 사용 패턴
2. **참조된 USS 파일 모두 읽기** — `<Style src="..."/>` 모두 추적
3. **정적 검증 항목** (text 분석으로 충분):

| 항목 | 검사 방법 |
|---|---|
| **name 일관성** | 모든 인터랙션 요소(Button, TextField 등)에 의미있는 name 있는지 |
| **인라인 스타일 비율** | `style="..."` 직접 박힌 element 수 / 전체 element 수 (낮을수록 좋음) |
| **USS 변수 사용률** | USS 내 `var(--*)` 사용 횟수 vs 하드코딩 색상(`#hex`, `rgb(`)/px |
| **하드코딩 px** | USS의 `px` 리터럴 빈도, 디자인 시스템 변수 누락 신호 |
| **클래스 일관성** | BEM 스타일 또는 프로젝트 컨벤션 준수 (예: `unity-`, `px-` 접두사) |
| **트리 깊이** | VisualElement 중첩 깊이가 8단계 이상이면 경고 |
| **선택자 충돌 가능성** | 같은 클래스에 서로 다른 USS가 다른 값을 주는지 |

> 정량 항목은 grep + Read로 충분하므로 별도 C# 헬퍼 없이 evaluator agent가 직접 수행한다.

```
- UXML 파일: {경로} (Read)
- USS 파일들: {경로 목록} (모두 Read)

## 평가 기준
Assets/Editor/UIAutomation/Data/criteria.md 의 5가지 기준 + 아래 추가 항목.

### 추가: AI 슬롭 체크리스트 (감점 요인)
다음 중 발견되면 명시하고 감점:
- 의미 없는 그라데이션 (특히 배경에 무지개/사이키)
- 일관성 깨진 코너 라운드 (한 화면에 4종 이상)
- 과도한 보더/외곽선 (3px 이상이 곳곳에)
- 빈 패널/플레이스홀더가 그대로 남음
- 폰트 weight 단일 사용 (전부 Regular 또는 전부 Bold)
- 색상 팔레트 폭발 (5색 이상의 무관한 계열)
- 아이콘 의미 없음 (장식용 반복)
- 계층 강조 부재 (모든 텍스트가 같은 무게/크기)

### 추가: 정적 분석 항목
위 Step 2의 7개 항목 결과를 보고서에 포함.

## 카테고리 판정
먼저 UXML 파일명/구조로 화면 카테고리를 판정:
- **경제**: 재련/강화/합성/소환/뽑기/상점/패스/결제 → 항목 6,7 적용 (분모 19)
- **전투/소셜/메타/튜토리얼/일반**: 항목 6,7 미적용 (분모 13)

## 출력 형식
각 평가 항목별:
- 점수 (1-5)
- 근거 (구체적 element name + 캡처 위치 — 좌상/중앙/하단 등)
- 개선 제안 (실행 가능한 액션, **반드시 파일:라인 명시**)
- **10/10 가이드** (한 줄, 단일 액션): "이 항목이 만점이 되려면 ___ 하세요"

> 개선 제안은 반드시 `TK_PopupX.uss:142` 또는 `TK_PopupX.uxml:33` 형식으로 정확한 위치를 명시한다. lite 모드의 강점이 정적 분석이므로 모호한 위치 표현(예: "헤더 우측")만 쓰지 말고 element name + 라인 번호를 같이 적어라.

## 자동 FAIL 룰 (criteria.md 참조)
다음 중 하나라도 해당하면 합격선과 무관하게 FAIL 판정:
- 어느 항목이라도 점수 ≤ 2
- 경제 화면인데 재화식별성 또는 확률신뢰성 ≤ 3
- AI 슬롭 누적 감점 -1.5 초과
- 한국 공정위 확률 표기 가이드 위반

마지막에:
- 가중 총점
- PASS/FAIL + 사유
- TL;DR (5분 / 30분 / 별도 작업) — **반드시 보고서 최상단에 작성**
- 우선 수정 항목 (점수 ≤ 2)

## 보고서 저장
경로: Assets/Editor/UIAutomation/Data/EvaluationReports/{UXML이름}_{YYYYMMDD}_lite.md
```

### Step 4: 시니어 디자이너 리뷰 (★ 정규 단계)

Step 3에서 만든 draft 보고서를 **모바일 게임 시니어 UI/UX 디자이너 페르소나 agent**에게 넘겨 2차 검토를 받는다. rubric 기반 평가는 누락이 많기 때문에 인간 시니어의 직관적 검토가 반드시 필요하다.

```
Agent(subagent_type="general-purpose") 에게 전달:

너는 모바일 게임 UI/UX 시니어 디자이너다. 10년차, 라이브 모바일 RPG/Idle 게임 다수 출시 경험.
디자인 시스템·정보 위계·터치 가이드라인·F2P 경제 화면(재화·등급·확률)에 강하다.
후배 evaluator agent가 만든 draft 보고서와 평가 대상을 검토해서 시니어 관점으로 솔직하게 피드백한다.

## 검토 대상
- Draft 보고서: {Step 3 결과 경로}
- 평가 대상 캡처 PNG: {경로}
- 평가 대상 UXML: {경로}
- 참조 USS: {목록}
- 평가 기준: Assets/Editor/UIAutomation/Data/criteria.md

## 컨텍스트
- 출시 전 모바일 idle RPG
- 화면 카테고리: {경제/전투/소셜/메타}
- (경제 화면이면) 매출 핵심 화면이라 시니어 기준은 더 빡빡함

## 두 축으로 피드백

### A. 보고서 검토
1. **놓친 중요 디자인 이슈** (중요도 순): rubric으로 못 잡는 도메인 지식 기반 이슈
2. **점수에 대한 이견**: 너무 후하거나 짠 항목 + 시니어가 본 정확한 점수
3. **개선 제안의 실용성**: 10/10 가이드가 행동 가능한가? 한 줄에 한 액션인가?
4. **첫 5분에 뭘 고칠지 명확한가**

### B. 카테고리별 도메인 체크 (경제 화면 한정)
- 재화 식별성: 실제 캡처에서 5종 이상 재화가 식별 가능한가?
- 확률 표기 신뢰성: 그룹×옵션 복합 확률, 단위 일관성, 공정위 가이드 충족?
- CTA 우선순위: 1차/2차 액션, 프리미엄/일반 색 의미 일관?
- 소비 액션 안전성: 환불 불가/되돌릴 수 없음 명시?
- 비용 라벨과 헤더 재화 매칭?

### C. 게임 UI 특유 슬롭 추가 검출
draft에 없을 수 있는 항목들:
- 무의미한 글로우/네온 발광
- 풀스크린 비네팅/스캔라인/그레인
- 빈 슬롯 플레이스홀더 패턴
- 재화 아이콘이 모두 동전형 (형태 차별화 X)
- 모든 라벨에 그림자 박힘
- 숫자 단위 표기 혼합 (1,234 / 1.25만 / 1234)
- 버튼 셰입 불일치 (원/사각/캡슐 혼재)

## 출력
다음 항목을 구조화된 마크다운으로:
- 잘 짚은 점 (3개)
- 놓친 이슈 (중요도 순, 각 항목에 파일:라인 또는 캡처 위치 명시)
- 점수 이견 (시니어가 본 정확 점수)
- 개선 제안 실용성 평가
- 시니어가 다시 매긴 가중 총점 + PASS/FAIL
- "지금 5분 안에 고칠 1개" — 시니어 버전

## 저장
{Draft 보고서 경로의 _v2.md 또는 _senior.md 버전} 으로 저장.
구조: draft 보고서 본문 그대로 + 맨 위에 "## 시니어 리뷰" 섹션 추가.
또는 draft를 시니어 평가로 덮어쓰는 새 보고서 생성 — 둘 다 OK.
```

### Step 5: 최종 보고서 (Synthesis)

evaluator draft + senior review를 합쳐 **하나의 최종 보고서**로 정리한다. 시니어가 점수를 수정한 항목은 시니어 점수 채택, 시니어가 추가한 누락 이슈는 보고서 본문에 통합, TL;DR 박스는 시니어의 "5분 안에 고칠 1개"로 갱신.

최종 보고서 경로: `Assets/Editor/UIAutomation/Data/EvaluationReports/{UXML이름}_{YYYYMMDD}_lite.md`
중간 산출물(draft, senior review 별도 파일)은 같은 폴더에 `_draft.md`, `_senior.md` 접미사로 보관.

> **왜 두 단계인가**: rubric 기반 evaluator는 *측정 가능한 항목*을 빠짐없이 채점하지만, 도메인 지식 기반 *놓친 이슈*는 못 잡는다. 시니어 페르소나 agent가 도메인 직관으로 보강하는 2단 평가가 단일 평가보다 신뢰도가 훨씬 높다 (1차 검증에서 입증됨).

### Step 6: 피드백 반영 (선택)

점수 ≤ 2인 항목이 있으면:
1. 개선 제안 + 10/10 가이드 확인
2. UXML/USS 직접 수정
3. Step 1로 다시 자동 캡처 (UXML 경로로 재호출 — 새 타임스탬프 PNG 생성)
4. **Before/After**를 같은 보고서에 추가 (덮어쓰지 말고 섹션 추가)

## 평가 기준 (요약, 상세는 criteria.md)

5가지 기본 항목 (가중 평균):
1. **정보 계층** (×3)
2. **터치 적합성** (×3) — UXML은 px 단위로 검증
3. **시각적 일관성** (×2) — 더미 데이터 + USS 변수 사용 검사 위주
4. **인지 부하** (×3)
5. **피드백 명확성** (×2) — 더미 상태로는 일부 제한, 가능한 범위만

추가 항목 (감점):
- **AI 슬롭** (총 -3점까지)

합격: 가중 총점 3.5/5.0 이상

| 속도 | 가장 빠름 | Runtime은 느림 |
| 정적 분석 | ✅ UXML/USS 텍스트 분석 | UGUI 구조 JSON |

## 주의사항

- **단색 여백 무시**: 자동 캡처의 여백은 캡처 배경(회색)이지 디자인이 아님. evaluator에게 명시.
- **항상 1920×1080 1:1**: 자동 캡처는 고정 해상도 풀 렌더라 줌/Fit viewport 조정이 필요 없다.
- **USS 누락 주의**: UXML이 참조하는 모든 USS를 따라가서 읽어야 함. `<Style src="..."/>` 전부 추적.
- **재평가 시 보고서 덮어쓰지 말 것**: Before/After 섹션을 같은 보고서에 추가하여 개선 흐름 보존.
