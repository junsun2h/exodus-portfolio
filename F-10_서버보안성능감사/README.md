# F-10. Firebase Functions 보안·성능 감사

> **코드 발췌 없음.** 이 항목은 전역 정책 변경·조사·설계 문서 형태의 작업이라
> 특정 파일로 잘라낼 수 없다. 아래 카드의 *근거* 항목이 실제 산출물이다.

**구간** Phase 1 (2025.07.22) | **포지션** 서버 | **AI** 보조 (감사)

- **문제**: 서버 코드베이스가 완성 단계에 접어들었지만, **1인 개발이라 코드 리뷰어가 없다.** 보안 구멍과 성능 병목을 스스로 찾아야 하는데, 자기 코드는 자기가 가장 안 보인다.
- **해결**: 서버 코드 전량을 AI에 읽혀 **보안·성능 관점의 감사 보고서**를 생성했다. AI를 "코드를 짜주는 도구"가 아니라 **"리뷰어 대체재"**로 먼저 도입한 것이 이 프로젝트 AI 활용의 출발점이다.
- **기술**: 전체 코드베이스 컨텍스트 투입 → 항목별 지적 → 보고서화
- **정량**: 확인 가능한 **첫 AI 산출 문서** (2025-07-22). 이 프로젝트의 AI 도입 기준선.
- **근거**: `FirebaseCLI/functions/Docs/plans/25.07.22_Firebase-Functions-프로젝트-보안-및-성능-감사-보고서.md`
- **면접 포인트**: AI 도입의 첫 용도가 **생성이 아니라 검증**이었다는 점. 1인 개발의 최대 약점(리뷰어 부재)을 정확히 겨냥했고, 이 판단이 Phase 3의 무인 감사 파이프라인(F-34)까지 일관되게 이어진다. **"AI에게 무엇을 시킬 것인가"를 처음부터 리뷰로 잡았다.**
- **슬라이드 자료**: 첫 감사 보고서 문서 캡처 (타임라인 기준선 표시용) — **캡처 필요**
