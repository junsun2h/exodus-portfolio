# F-27. AI 협업 인프라 자체 구축

> **코드 발췌 없음.** 이 항목은 전역 정책 변경·조사·설계 문서 형태의 작업이라
> 특정 파일로 잘라낼 수 없다. 아래 카드의 *근거* 항목이 실제 산출물이다.

**구간** Phase 2 (2026.01 ~ 02) | **포지션** TD | **AI** 협업

- **문제**: AI에게 같은 종류의 작업을 반복 요청하면 **매번 배경 설명부터 다시 해야 하고, 결과 품질이 매번 달라진다.** 밸런스 분석, 상품 설계, UI 평가처럼 이 프로젝트에 특화된 작업일수록 심하다. 게다가 컨텍스트가 길어지면 정작 필요한 정보가 밀려난다.
- **해결**: **도메인 특화 커스텀 스킬·커맨드를 직접 만들어** 반복 작업을 규격화했다.

| 영역 | 스킬/커맨드 |
|---|---|
| 배틀 밸런스 | `battlebalance` 계열 8종 (빌드/스테이지/콘텐츠/피해계산 인덱스 등) |
| 상품 설계 | `bm-sangpum` 계열 — **멀티 페르소나 논의**(4명의 전문가 에이전트가 다각도 검토), 포트폴리오 생성, 시트 업로드 |
| 데이터 | CoreData 생성기, GameDB 업로드, AchieveItemConfig CS↔TS 동기화 |
| UI | UI 평가, UGUI 폴리싱, UXML 변환 |
| 문서 | 위키 추가, INDEX 갱신, 플랜 아카이브 |

  - **Context Limit 최적화**를 별도 작업으로 다뤘다. 스킬 파일에 원본 문서 데이터를 복사하지 않고 **경로만 참조**하는 규칙을 세워, 스킬 자체가 컨텍스트를 잡아먹지 않게 했다.
- **기술**: Claude Code 커스텀 스킬/슬래시 커맨드 작성, 멀티 에이전트 페르소나 설계, 컨텍스트 예산 관리
- **정량**: 커스텀 커맨드 **31종** + 스킬 8종 (2026-08 현재)

- **면접 포인트**: **AI 협업을 "요령"이 아니라 "인프라"로 다뤘다.** 프롬프트를 잘 쓰는 것이 아니라, 반복 작업을 스킬로 고정해 **매번 같은 품질이 나오게** 만들었다. 특히 상품 설계의 멀티 페르소나 스킬(4명이 각자 관점으로 검토)은 1인 개발에서 **의도적으로 관점을 늘리는** 장치다. Context Limit을 별도 최적화 과제로 잡은 것은 컨텍스트를 유한 자원으로 인식했다는 뜻 — Phase 3의 토큰 절약 훅(F-49)으로 이어진다.
