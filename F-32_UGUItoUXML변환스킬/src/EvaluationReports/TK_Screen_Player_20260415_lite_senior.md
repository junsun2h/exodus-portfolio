### 2. 드래프트가 놓친 이슈 (중요도 순)

#### [치명] #1. CTA 과잉 — 화면 내 "초록 느낌 버튼" 5개 + 노랑 primary 3개가 동시 활성 (캡처 우측 카드 스택, 좌측 하단 `btn-profile-*`)

### 5. 첫 5분 안에 고칠 1개 — 시니어 버전

> 드래프트의 "6슬롯 색 placeholder 인라인 주입"보다 **상위 개선**:

**`.ps-mod-slot`의 모든 카드에 "5.000% → 5.0%" 일괄 치환 + 비활성 상태 카드에 `.ps-mod-slot--locked` 클래스 부여 (회색 컷 + 자물쇠 아이콘 + 비용 숨김)**

이유:
1. 재화 슬롯 색 주입은 "아이콘이 없으니 솔리드 컬러 박스 6개"로 끝나 본질적 식별 개선이 안 됨 → **아이콘 에셋 작업과 세트**여야 점수가 오름. 5분으로 끝낼 작업 아님.
2. 반면 **소수점 정리 + 잠금 카드 분리**는 UXML/USS만으로 5분에 끝나고, 항목 4(인지부하)·5(피드백)·7(신뢰성) **세 축에 동시 반영**되어 2점짜리 세 개가 3점으로 올라온다. 합계 기준 +9점 (19 분모로 +0.47).
3. 동시에 "잠겨 있는데 버튼 활성" 안티패턴이 해소되어 매출 집행 측면의 "오결제" 리스크가 사라진다 — 시니어가 릴리즈 블로커로 치는 종류.

구체 액션(한 줄씩):
- `uxml:84,94,119,129,139`: `N.000%` → `N.0%` 일괄.
- `uxml:94` (이속 잠금): 하위 라벨에서 `0.000%` 제거, 카드 class에 `ps-mod-slot--locked` 추가.
- `uxml:139,149` (레벨/재화 부족): 동일 class 추가.
- `uxml:106` (MAX): `ps-mod-slot--maxed` class + 구매 버튼 제거 또는 `btn-disabled` 변형.
- `uss` 하단 신규: `.ps-mod-slot--locked { opacity: 0.55; } .ps-mod-slot--locked .ps-mod-buy { display: none; } .ps-mod-slot--locked::before { ... 자물쇠 }` (UI Toolkit에 ::before 제약 있으면 별도 VisualElement로).

이 한 방으로 **FAIL 항목 5개 중 3개가 3점으로 복귀**한다. 재화 아이콘 작업은 그 다음 30분 task.

### 6. 시니어 총평

드래프트는 체크리스트 커버리지는 훌륭하다. 그러나 **"각 항목을 기준에 비추어 약간 후하게 주는" 경향**이 있다 — 규칙 위반을 인지한 항목에 4점을 주거나, 안티패턴을 지적하면서 3점으로 두는 식. 경제 화면은 "보통" 허용선이 없고 2점 이하면 릴리즈 불가라는 점을 더 단호하게 반영해야 한다.

이 화면은 현재 상태로는 **재화 아이콘 에셋 주입 + 추천 강조 + 좌측 패널 CP/스탯 재구성**의 세 작업이 선행되지 않으면 매출 집행이 불가능한 수준이다. UXML/USS 차원에서만 가능한 5분 수정을 최대치로 짜내면 2.05 → 약 2.6까지 끌어올릴 수 있으나, 4.0 합격선까지는 디자이너 에셋 작업이 **필수 전제**다.
