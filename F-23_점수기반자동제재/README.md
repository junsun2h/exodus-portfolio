# F-23. 점수 기반 자동 계정 제재

> 소스 발췌: `src/` — 2개 파일

**구간** Phase 2 (2026.02.02) | **포지션** 서버 | **AI** 협업

- **문제**: F-22가 위협을 **탐지**하지만, 탐지 후 무엇을 할지가 없었다. 탐지될 때마다 즉시 정지하면 오탐 한 번에 정상 유저가 밴되고, 사람이 판단하면 1인 개발에서 감당이 안 된다.
- **해결**: **위협을 점수로 환산해 누적**하고, 점수 구간에 따라 자동 조치를 단계적으로 올린다.

| 위협 유형 | 가중치 |
|---|---:|
| APK 변조 | 60 |
| 스피드핵 | 50 |
| 인젝션 | 40 |
| 시간 조작 | 30 |
| 루팅 | 10 |

  조치 단계: `None` → `Monitoring` → `FeatureRestricted` → `Suspended`

  가중치 설계가 요점이다. **루팅 10점**은 그 자체로는 제재하지 않는다(정상 유저도 루팅한다). 하지만 루팅 + 인젝션이면 50점으로 조치 구간에 진입한다. **단일 신호로 판정하지 않고 조합으로 판정한다.**
- **기술**: 위협 가중치 누적 스코어링, 4단계 자동 조치 상태 전이, 서버 측 판정
- **정량**: 위협 유형 **5종** / 조치 **4단계** / 완전 자동
- **근거**: `Docs/plans/26.02.02_점수-기반-계정-정지-시스템-구현-명세서.md`
- **면접 포인트**: **"오탐 비용과 미탐 비용을 가중치로 설계했다."** 보안 시스템에서 가장 어려운 것은 탐지가 아니라 **탐지 후 판단**이다. 루팅에 10점만 주고 APK 변조에 60점을 준 것은 각 신호의 신뢰도를 명시적으로 수치화한 것이며, 1인 개발에서 운영 인력 없이 제재를 돌리기 위한 필수 조건이다.
- **슬라이드 자료**: 가중치 표 + 4단계 전이 다이어그램 — **다이어그램 필요**
