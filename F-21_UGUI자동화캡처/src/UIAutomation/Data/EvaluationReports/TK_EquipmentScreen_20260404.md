## 1. 정보 계층 -- 4/5

**근거**

- **폰트 크기 비율 양호**: 메인 스탯 값(26px)이 보조 스탯(17px)에 비해 약 1.53배로, 1.5배 기준을 간신히 충족한다. 장비명(28px) vs 스탯명(17px)은 1.65배로 충분한 계층 분리.
- **주요 행동 버튼 하단 배치**: 좌측 하단 4개 버튼(56px)과 우측 하단 3개 액션 버튼(56px)이 모두 화면 최하단에 위치하여 엄지 접근성 확보. 강화 버튼도 우측 중간에 별도 배치되어 시선 유도가 명확.
- **탭 선택 상태 구분**: `es-tab-active` 클래스에서 `border-bottom: 4px cyan`, `color: cyan`으로 활성 탭을 명확히 구분. 서브탭도 `tab-item-active` 클래스 별도 존재.
- **메인 스탯 강조 우수**: 골든 배경(`rgba(255,210,75,0.08)`) + 좌측 3px 골든 보더 + 골든 텍스트로 메인 스탯 행이 다른 스탯 행과 확연히 구분됨.
- **섹션별 색상 구분**: 일반(시안), 보유(녹색), 고유(레드)로 섹션 타이틀 색상이 분리되어 정보 카테고리 인지에 효과적.

**감점 요인**

- **빈 상태 안내 부재**: 장비 미보유 시 빈 그리드에 대한 "장비소환으로 첫 장비를 획득하세요" 같은 안내 텍스트(empty state)가 UXML에 없음.
- **재화 값 12px**: 상단 바의 재화 텍스트가 12px로, 1920x1080에서 실 디바이스(6~7인치) 기준 약 3.5~4dp 수준이라 매우 작다. 최소 16px 권장.

**개선 제안**

1. 빈 상태용 `es-empty-state` VisualElement + 안내 텍스트 + CTA 버튼 추가
2. `wealth-value` 폰트 크기 12px -> 16px 상향 (최소 가독성 확보)

## 2. 터치 적합성 -- 3/5

**근거**

- **뒤로가기 버튼(64x64px)**: Apple HIG 44pt / Material 48dp 기준 모두 충족. 음수 마진(`left: -12px`)으로 터치 영역이 패딩 외부까지 확장되어 우수.
- **메인 탭(flex-grow x 72px)**: 1920의 55% = 1056px 중 3분할이면 각 ~352px x 72px. 터치 영역 충분.
- **서브 탭(flex-grow x 52px)**: 5분할 시 각 ~211px x 52px. 높이 52px으로 44px 기준 충족.
- **하단/액션 버튼(flex-grow x 56px)**: 충분한 크기.
- **장비 슬롯(155px x ~180px+)**: 터치 대상으로 충분한 크기.

**심각한 문제**

- **닫기 버튼(btn-close) 크기 충돌**: PXTopBar.uss에서 `.btn-close`는 40x40px로 정의되고, PXButton.uss에서는 48x48px로 정의된다. CSS 캐스케이드 순서에 따라 어느 것이 적용될지 불확실하나, 40px 적용 시 44px 최소 기준 미달. 또한 `right: -12px` 음수 위치로 화면 경계에 밀착되어 오터치 위험.
- **강화 정보 버튼(btn-reinforce-info) 28x28px**: 44px 최소 기준 대비 64%에 불과. 사실상 탭 불가능한 크기. 아이콘 자체 28px이라도 터치 영역(padding/margin)으로 44px 확보가 필요하지만 현재 `padding: 0`.
- **인접 버튼 간격**: 하단 버튼들 `margin: 0 4px` = 좌우 각 4px이므로, 인접 버튼 간 실제 간격은 8px. 기준선 충족이지만 여유 없음. 4개 버튼이 한 줄에 밀집되어 오터치 리스크.
- **재화 아이콘(20x20px)**: 터치 대상이 아닐 수 있으나, 탭하여 상세 보기가 일반적인 idle RPG 패턴이라면 44px 미달.

**개선 제안**

1. `btn-close` 크기를 48x48px로 통일 (PXTopBar.uss 수정)
2. `btn-reinforce-info`에 `padding: 8px` 추가하여 실제 터치 영역 44x44px 확보
3. 하단 4개 버튼을 3개로 축소하거나, 2행 배치 검토 (밀집도 완화)
4. 재화 아이콘+값 묶어서 최소 44px 높이 터치 영역 확보

## 3. 시각적 일관성 -- 4/5

**근거**

- **버튼 색상-의미 매핑 우수**: PXButton.uss 주석에 명시된 규칙(골드=결정, 레드=성장, 녹색=적용, 네이비=취소)이 UXML에서 정확히 준수됨.
  - `btn-primary`(골드): 일괄승급, 승급 MAX
  - `btn-power`(레드): 강화
  - `btn-positive`(녹색): 장착
  - `btn-cancel`(네이비): 옵션변경
  - `btn-nav`(틸+외곽선): 장비도감, 장비소환, 추천장착
- **폰트 크기 계층 준수**: 제목 32px > 장비명 28px > 메인값 26px > 탭 22px > 버튼/서브탭 20px > 섹션 18px > 스탯행 17px > 캡션 16px > 재화 12px. 10단계로 과도하게 세분화되어 있지만, 각 단계 간 차이가 명확.
- **등급별 색상 체계**: 6등급(common~mythic)에 대해 border, background, tier-badge 색상이 PXColors.uss의 `--color-grade-*` 변수와 일관되게 적용.
- **hover/active 상태**: 모든 버튼 유형에 hover(밝아짐), active(어두워짐) 트랜지션이 0.15s로 통일.

**감점 요인**

- **폰트 크기 계층 과다**: 12px~32px 사이에 10단계(12, 14, 16, 17, 18, 20, 22, 24, 26, 28, 32)는 시각적으로 구분하기 어려운 1~2px 차이가 다수 (16/17, 17/18, 20/22). 5~6단계로 축소 권장.

**개선 제안**

1. 폰트 크기 계층을 정리: 14 / 18 / 22 / 26 / 32 (5단계) 또는 14 / 16 / 20 / 24 / 28 / 32 (6단계)로 통합

## 4. 인지 부하 -- 3/5

**근거**

- **수치 단축 포맷 사용**: "9.10억", "2,779.96만" 등 한국어 단위 축약 사용으로 긴 숫자열 회피. 양호.
- **탭 개수**: 메인탭 3개 + 서브탭 5개로, 각각은 5개 이하 기준 충족.
- **스크롤 없이 핵심 정보**: 메인 스탯 + 일반 옵션 4행은 스크롤 없이 보일 가능성 높으나, 보유/고유 옵션까지 합치면 15행 이상(메인1 + 일반4 + 보유3 + 고유4 + 섹션타이틀3 = 15행)으로 반드시 스크롤 필요.

**심각한 문제**

- **1차 행동 버튼 과다**: 한 화면에 동시 노출되는 행동 버튼이 **8개**(하단 4 + 액션 3 + 강화 1). 기준은 1차 행동 버튼 2개 이하인데, 현재 "강화", "승급 MAX", "장착" 3개가 모두 1차 행동으로 경쟁하고 있다. 유저 입장에서 "지금 뭘 눌러야 하지?"라는 결정 피로도 발생.
- **좌측 하단 버튼 4개**: "장비도감", "장비소환", "추천장착", "일괄승급"이 모두 같은 크기(flex-grow)로 나열되어 우선순위가 불명확. 특히 "일괄승급"은 `btn-primary`(골드)로 차별화했지만, 나머지 3개 `btn-nav` 간에는 구분이 없다.
- **재화 6종 동시 표시**: 상단 바에 6개 재화 아이콘+값이 나열. 현재 선택된 장비의 강화에 필요한 재화만 강조하고 나머지를 희미하게 하는 것이 더 효과적.
- **우측 패널 정보 밀도**: 장비명 + 카드 + 강화버튼 + 성공률 + 15행 스탯 + 3개 액션 버튼이 45% 영역에 집중. "벽돌 UI" 경향.

**개선 제안**

1. 좌측 하단 버튼 축소: "장비도감", "장비소환"을 상단 바 아이콘이나 탭으로 이동 (2개 제거 -> 2개 유지)
2. 우측 패널 액션 버튼: 현재 상태에 따라 1개만 강조 (장비 미장착이면 "장착"만 Primary, 나머지 dimmed)
3. 재화 바: 현재 장비 등급에 해당하는 재화만 하이라이트, 나머지 opacity 0.4
4. 스탯 목록: 기본은 메인스탯+일반옵션만 표시, "상세보기" 펼침으로 보유/고유 옵션 표시

## 5. 피드백 명확성 -- 3/5

**근거**

- **pressed/disabled 상태 존재**: PXButton.uss에 `:active`(pressed) 상태가 모든 버튼 유형에 정의됨. `:disabled` 상태도 `btn-disabled` 색상 + `color-text-disabled`로 시각적 구분.
- **등급별 슬롯 테두리 + 배경색**: 선택 상태(`es-slot-selected`)는 4px 흰색 보더 + 15% 흰색 배경으로 뚜렷한 하이라이트. 장착 상태(`es-slot-equipped`)는 레드 보더. 빈 슬롯(`es-slot-empty`)은 opacity 0.3.
- **승급 가능 표시**: `es-count-promotable` 클래스에서 진행바 fill 색상을 `color-text-positive`(녹색)으로 변경하여 승급 가능 여부를 시각적으로 피드백.
- **강화 성공률 표시**: `es-success-rate-label`에 "MAX" 텍스트 + accent 색상(골든)으로 표시.

**감점 요인**

- **재화 부족 시 피드백 불명확**: 강화 버튼의 비용 "(9.10억)"이 표시되지만, 재화 부족 시 비용을 빨간색으로 변경하거나 부족량을 표시하는 별도 클래스가 USS에 없음. disabled 상태만으로는 "왜 못 누르는지" 전달 불충분.
- **레드닷(tk-reddot) 정의 불완전**: TK_EquipSlot.uxml에 `tk-reddot` 요소가 있지만, 표시/숨김 로직이나 위치가 USS에서 명시되지 않음 (C# 런타임 제어 추정). 선택 카드에서는 `display: none`으로 숨김 처리만 확인.
- **장착/해제 토글**: 현재 `btn-equip` 텍스트가 "장착"으로 고정. 이미 장착된 장비 선택 시 "해제"로 변경되는지 UXML만으로는 확인 불가 (C# 런타임 추정). 하지만 색상 변화(positive->cancel 등)에 대한 USS 정의가 없어, 토글 상태의 시각적 전환이 부족할 수 있음.
- **강화 실패 피드백**: 강화 실패 시의 시각적 피드백(셰이크, 색상 변화 등)에 대한 USS 정의 없음. 런타임 처리 추정이지만 구조적 준비가 부재.

**개선 제안**

1. `es-reinforce-btn-count`에 `.insufficient` 클래스 추가: `color: var(--color-text-negative)` + 부족량 텍스트 형식 "(부족: 3.2억)"
2. 레드닷 위치/크기를 USS에 명시적으로 정의 (슬롯 우상단 12x12px 등)
3. 장착 버튼 토글용 클래스 추가: `.es-btn-unequip { background-color: var(--color-btn-cancel); }`
4. 강화 실패/성공 애니메이션 트랜지션 정의

## 우선 수정 항목

2점 이하 항목은 없으나, 3점 항목이 3개로 합격선(3.5) 미달. 다음을 우선 수정:

### [긴급] 터치 적합성 개선
1. **`btn-reinforce-info` 28x28 -> 44x44 터치 영역 확보**: padding 8px 추가 또는 크기 자체를 44x44로 확대
2. **`btn-close` 크기 통일**: PXTopBar.uss의 40x40 -> 48x48로 상향 (PXButton.uss와 일치)
3. **재화 영역 터치 대상화**: wealth-item에 min-height: 44px 적용

### [높음] 인지 부하 경감
4. **좌측 하단 버튼 4->2 축소**: "장비도감"/"장비소환"을 별도 진입점(상단 아이콘 또는 탭)으로 분리
5. **재화 6종 중 관련 재화 하이라이트**: 현재 장비 등급 재화만 강조, 나머지 dimmed
6. **우측 액션 버튼 맥락별 1개 강조**: 상태에 따라 Primary 버튼 1개만 골드, 나머지 Nav/Cancel 톤

### [중간] 피드백 보강
7. **재화 부족 시 빨간색 비용 표시**: `.es-reinforce-btn-count.insufficient` 클래스
8. **빈 상태 안내 텍스트 추가**: 장비 0개 시 그리드 영역에 CTA 안내
9. **장착/해제 토글 시각 전환**: 버튼 색상 + 텍스트 동시 변경

### [낮음] 가독성
10. **재화 값 12px -> 16px**: 최소 가독성 확보
11. **폰트 크기 계층 정리**: 10단계 -> 6단계로 축소
