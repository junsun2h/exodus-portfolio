## 1. 정보 계층 — 4/5

**근거**:
- 핵심 스탯 값(es-stat-value-highlight)이 24px + accent 색상(골드 #FFD24B)으로 일반 스탯(18px)과 명확히 구분됨. 1.33배 크기 차이로 기준(1.5배)에 근접하지만 색상 대비가 이를 보완
- 장비 이름이 28px bold로 두번째 시각 우선순위를 차지하며, 우측 패널 최상단에 bg-tertiary 배경으로 영역 분리
- 탭 활성 상태가 border-bottom 4px cyan + 텍스트 색 변경(--color-text-cyan)으로 이중 시각 피드백 제공
- 등급별 슬롯 배경/테두리 색상이 6단계로 분화되어 아이템 등급 즉시 인지 가능
- 재화 바가 상단 고정으로 콘텐츠를 가리지 않으면서 항상 접근 가능

**개선 제안**:
- 핵심 스탯(주요 피해 증가) 폰트를 26~28px로 올려 1.5배 기준을 정확히 충족시키면 더 명확
- 강화 전후 스탯 비교(증감 표시)가 UXML 구조에 없음. C#에서 동적으로 추가하더라도 `es-stat-delta-positive/negative` 같은 USS 클래스를 미리 정의해두면 좋음
- 빈 상태(장비 미선택)에서 "장비를 선택하세요" 같은 가이드가 구조에 보이지 않음 (C#에서 처리할 수 있으나, UXML에 placeholder 요소가 있으면 디자인 일관성 확보)

## 2. 터치 적합성 — 4/5

**근거**:
- btn-back: 64x64로 충분 (44px 기준 대비 145%)
- 메인 탭: flex-grow x 72px로 넉넉한 터치 영역
- 서브 탭: flex-grow x 52px로 44px 최소 기준 충족
- 하단 버튼: flex-grow x 56px, margin 4px 간격
- 액션 버튼(승급/옵션변경/장착): flex-grow x 60px으로 충분
- 강화 버튼: min-width 150px, padding 10px 24px으로 넉넉
- 장비 슬롯: 155px wide x ~200px estimated height로 그리드 터치에 충분
- 인접 버튼 간격: 하단/액션 버튼 모두 margin 0 4px로 8px 간격 확보

**주의점**:
- btn-close가 PXTopBar.uss에서 40x40으로 정의됨. PXButton.uss에서는 48x48이지만, 두 USS가 동시 적용될 때 cascade 순서에 따라 40x40이 될 수 있음. 44px 미만이므로 터치 미스 위험
- 재화 아이콘(wealth-icon)이 20x20으로 매우 작으나, 인터랙티브 요소가 아닌 순수 표시용이므로 문제 아님
- 강화 버튼과 액션 버튼이 우측 패널에 집중되어 있어, 랜드스케이프 기준 하단 60% 영역 내에 위치 (세로 레이아웃상 강화 섹션은 중앙, 액션 버튼은 하단)

**개선 제안**:
- btn-close를 최소 44x44로 통일. PXTopBar.uss의 `.btn-close` 크기를 44px로 상향 권장
- 서브 탭이 5개 나열되므로, 화면 폭 55%의 1/5 = 약 211px/5 = ~42px per tab (가로 기준). 1920 기준이면 1920*0.55/5 = ~211px로 충분하지만, 저해상도 디바이스에서 검증 필요

## 3. 시각적 일관성 — 4/5

**근거**:
- **버튼 색상 규칙 완벽 준수**: btn-primary(골드 #EBC33C), btn-power(레드 #C83232), btn-positive(그린 #48D080), btn-cancel(네이비+시안보더), btn-nav(네이비 #223250) 모두 PXColors.uss 변수 참조
- **PXTheme.tss 공유 테마** 사용으로 프로젝트 전체 일관성 확보
- **폰트 크기 계층**이 명확: 32(타이틀) > 28(장비명) > 24(핵심스탯/버튼) > 22(메인탭/액션) > 20(서브탭/섹션/강화) > 18(스탯행) > 16(티어/카운트) > 14(배지) > 12(재화). 9단계로 다소 세분화되어 있으나 역할별로 잘 구분
- **팝업 구조 패턴 준수**: 상단바(top-bar) + 콘텐츠(main-content) + 하단 행동 버튼(bottom-buttons / action-buttons)
- **등급 컬러** 6단계가 PXColors.uss의 --color-grade-* 변수와 일치
- CSS 변수(custom properties) 활용으로 하드코딩 색상값 최소화

**개선 제안**:
- 폰트 크기 9단계는 약간 과다. 22px와 24px의 차이(메인탭 vs 핵심스탯)가 시각적으로 구분하기 어려울 수 있음. 7단계 이하로 통합 검토
- es-top-title에서 font-size를 32px로 오버라이드하고 있으나, 기본 top-title은 26px. 화면별 오버라이드가 많아지면 일관성 저하 우려 -- 필요시 공통 클래스로 분리

## 4. 인지 부하 — 3/5

**근거**:
- **버튼 과다**: 한 화면에 16개 인터랙티브 요소(back, close, 탭 3+5, 하단 4, 강화 1, 액션 3). 특히 좌측 하단 4개 + 우측 하단 3개 = 7개 행동 버튼이 동시 노출
- **1차 행동 버튼 2개 이하 기준 미충족**: 좌측에 "일괄승급"(primary), 우측에 "승급"(primary) + "강화"(power) + "장착"(positive) = 1차 행동 후보가 4개. 사용자가 "지금 뭘 눌러야 하지?"를 판단하는 데 인지 비용 발생
- **좌우 분할 레이아웃**은 정보 그룹핑에 효과적이나, 각 패널에 독립적인 버튼 세트가 있어 시선 분산
- **탭 구조**: 메인 3개 + 서브 5개 = 8개 탭. 기준(5개 이하)을 초과하나, 메인/서브 분리로 단계적 노출이므로 실제 인지 부하는 완화됨
- **스크롤 영역 2개**(장비 그리드 + 스탯 목록)는 적절. 핵심 정보(강화 버튼, 액션 버튼)가 스크롤 밖에 고정(flex-shrink: 0)되어 묻히지 않음
- **재화 6종**이 상단에 동시 표시. 장비 강화에 실제 사용되는 재화만 강조하고 나머지를 축소하면 인지 부하 감소

**개선 제안**:
- 좌측 하단 4개 버튼 중 "장비도감", "장비소환"은 네비게이션이므로 상단바나 별도 메뉴로 이동 검토. 하단에는 "추천장착" + "일괄승급" 2개만 남기면 깔끔
- 우측 액션 버튼 3개(승급/옵션변경/장착) 중 상황에 따라 비활성화하여 실질적으로 1-2개만 활성 상태로 유지하면 의사결정 단순화 (C# 로직으로 처리 가능)
- 재화 바에서 현재 선택된 장비의 강화/승급에 필요한 재화만 하이라이트하고 나머지는 opacity 감소 처리

## 5. 피드백 명확성 — 4/5

**근거**:
- **버튼 상태 체계 완비**: 모든 버튼 유형(primary, cancel, positive, power, nav)에 hover/active/disabled 상태가 USS에 정의됨
- **disabled 상태**: 공통 disabled 스타일(bg-disabled + text-disabled + border-default)로 비활성이 시각적으로 명확
- **슬롯 상태 3종** 정의: es-slot-selected(글로우 보더 + 파란 배경), es-slot-equipped(레드 보더), es-slot-empty(opacity 0.3)
- **레드닷(tk-reddot)** 존재: 슬롯에 신규/업그레이드 가능 알림 표시 가능. 선택 카드에서는 display:none으로 적절히 숨김
- **승급 가능 표시**: es-count-promotable 클래스로 프로그레스 바 fill 색상이 positive 색으로 변경
- **강화 성공 확률** 실시간 표시(es-success-rate-label, accent 색상)

**개선 제안**:
- disabled 상태에서 "왜 비활성인지" 이유를 표시하는 툴팁/라벨이 UXML 구조에 없음. 재화 부족 시 "골드 부족" 같은 인라인 메시지 영역을 추가하면 피드백 명확성 향상
- 장착/해제 토글 상태가 btn-equip 텍스트 변경("장착"/"해제")으로만 구분되는 것으로 보임. 버튼 색상도 함께 전환(positive<->cancel)하면 더 명확
- 강화 성공/실패 시 시각 피드백(애니메이션, 색상 변화)은 C# 런타임 영역이므로 UXML만으로는 평가 한계
