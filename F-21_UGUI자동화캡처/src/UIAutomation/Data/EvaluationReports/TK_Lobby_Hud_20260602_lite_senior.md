### 1. 잘 짚은 점 3개

1. **자동도전 토글 34×34 미달 적발** (`uss:543-544`) — idle RPG에서 가장 빈번한 토글이 화면 내 최소 터치 타겟이라는 통찰은 정확하다. "5분 수정"으로 올린 우선순위도 옳다.
2. **placeholder 를 슬롭으로 오판하지 않음** — 단일 `Icon_Warning.png` 공유를 "의도된 아틀라싱"으로 컨텍스트에 맞게 제외 처리한 판단이 성숙하다. 초보 evaluator 가 가장 흔히 틀리는 지점을 피했다.
3. **토큰화/인라인 스타일 정적 분석** — hex 하드코딩 0, `var()` 56회, 인라인 style 3.0%, 트리 깊이 6단 등 유지보수 품질 지표를 정량화해 시각일관성 5점의 근거를 객관화했다. 이 부분은 그대로 인정.

### 2. 놓친 이슈 (중요도 순)

#### 🔴 [중대] M1. 무게중심이 좌측에 완전히 쏠림 — 우측 미들이 죽은 공간
캡처 확인: 좌상~좌중(재화/프로필/EXP/HP/MP/버프/성운/퀘스트)에 정보가 전부 몰려 있고, **화면 우측 절반 미들 영역이 통째로 비어 있다**. 로비 허브에서 우측 공백은 (a) 시선 균형 붕괴 (b) **오른손 엄지존(우측 중하단)이 비어 1차 액션 도달성 손해**로 직결된다. draft 의 정보계층 4점은 "좌상단 6단 과밀"만 지적하고 이 **전역 비대칭**을 놓쳤다.
- 위치: 캡처 우측 미들 전 영역 / 구조상 `lh-left-mid`(uss:62, left:16 width:380)만 좌측 중앙에 있고 대칭 우측 region 부재.
- 처방: 성운 행 또는 퀘스트 카드 중 하나를 우측으로 옮기거나, 우측 미들에 일일임무/출석 같은 2차 진입 카드를 배치해 좌우 균형 + 엄지존 활용.

#### 🔴 [중대] M2. 중앙 세로축에 포커스 2개가 충돌 (보스경고 vs 보상받기 CTA)
`lh-boss-alert`(uss:841, 풀스크린 센터, 64px negative)과 `dp-shortcut-alarm` "보상 받기"(중앙 하단 bottom:230px) — **둘 다 화면 정중앙 세로축**에 있다. 캡처에서 "보스 출현"(y≈383)과 "보상 받기"(y≈505)가 같은 컬럼에 수직 스택되어, 보스 출현 시 가장 중요한 1차 행동(전투 핵심)인 우하단 주문 슬롯이 아니라 **중앙의 두 텍스트가 시선을 양분**한다. idle 허브에서 "지금 봐야 할 단 하나"가 모호해지는 전형적 안티패턴. draft 는 보스경고/알람을 각각 "좋은 능동 표시"로만 평가하고 **둘의 공간 충돌**을 못 봤다.
- 처방: 보스경고는 상단 1/3 또는 스테이지 정보 근처 배너로, 보상받기는 우측 엄지존으로 분리 — 중앙 세로축에 동시 2포커스 금지.

#### 🟡 [중요] M3. 숫자 단위 표기 혼재 (draft 가 "일관"으로 오판한 항목)
draft 인지부하 항목은 "수치 단축 포맷 일관"이라 적었으나 **실제로는 혼재**다:
- `12,480`(콤마) / `8.42M`(축약) / `1,284,500`(콤마, ≈1.28M인데 풀자릿) / `6.4K`·`12.5K`·`x1.5K`(K) / `320/580`(생자릿) — 같은 좌측 컬럼 안에서 콤마/만·K·M/생자릿이 섞임.
- 특히 **전투력 `1,284,500` 풀자릿 vs 골드 `8.42M` 축약**의 충돌이 눈에 띈다(둘 다 100만+인데 표기 규칙이 다름). criteria 항목6 안티패턴("1.25만 / 8,520 혼합")과 동일 결함이 비경제 화면에도 그대로 존재.
- 위치: `uxml:17,21,31,42,48,52,124`.
- 처방: 표기 정책 1개 확정(예: 1,000 미만 생자릿 / 1만~ K·M 축약 / 강조 수치만 풀콤마). 인지부하 감점 사유로 추가.

#### 🟡 [중요] M4. 두 내비 영역(상단 메뉴 5 + 하단 탭 6)의 위계 차별화는 "있으나 약함"
프롬프트가 물은 구조 판단: 코드상 탭(132×120, 아이콘64, 라벨22px)이 메뉴(92×92, 아이콘52, 라벨16px)보다 크게 설계되어 **크기 위계는 존재**한다(draft 미언급). 다만 캡처에선 둘 다 동일 빨강 삼각형 + 무배경이라 **"두 줄의 역할 차이"가 위치(상/하)로만 전달**된다. placeholder 한계가 큰 부분이나, 출시 후에도 (a) 하단 탭에 약한 베이스/구분선 또는 선택 인디케이터를 주고 (b) 상단 메뉴는 더 가볍게 유지하는 식의 **항구적 위계 장치 1개**는 아트와 무관하게 지금 넣을 가치가 있다. → "단순 placeholder 한계"라기보다 **선택상태 인디케이터 부재(M5)와 결합된 구조 이슈**.

#### 🟡 [중요] M5. 선택/활성 상태 시각 부재 — draft 가 5번에서 언급했으나 과소평가
draft 피드백명확성 3.4는 pressed/active 부재를 적긴 했으나 **로비 허브에서 이건 "사소한 누락"이 아니라 동선의 핵심**이다. 하단 탭은 영구 네비라 "지금 어느 컨텍스트인가"를 선택상태로 알려야 하는데 `:checked`/active 클래스가 USS에 0개. idle 유저는 주의력 낮은 상태로 탭을 누르므로 "눌렀는데 반응 없음 + 어디 있는지 모름"이 이탈 요인. 점수를 더 낮게 봐야 함.

#### 🔵 [경미] M6. 최적화 일관성에 작은 균열 — boss-title `text-shadow`
USS 헤더·draft 슬롭표 모두 "TKBoxShadow/그림자 미사용(드로우콜 회피)"을 최적화 근거로 들지만, `lh-boss-title`(uss:855)에 `text-shadow: 0 2px 8px` 가 있다. 풀스크린 위에 뜨는 단발 오버레이라 실무상 문제는 없으나, **"그림자 0" 서술과 코드가 불일치**하므로 보고서 정확성 차원에서 각주 필요. 라벨 그림자 슬롭(모든 라벨에 그림자)은 아니므로 감점은 아님.

#### 🔵 [경미] M7. 진행바 5종 동시 노출 — draft 가 지적은 했으나 색 구분 검증 누락
EXP(xp색)/스테이지(기본)/타이머(기본)/HP(hp색)/MP(기본) 중 **스테이지·타이머·MP가 모두 `--color-progress-fill` 동일색**(uss:462,522)이다. 캡처에서도 상단 중앙 두 바가 같은 파랑 계열이라 "진행도 바"와 "남은시간 바"가 색으로 구분되지 않는다. 전투 중 슬쩍 봤을 때 "남은 시간"과 "스테이지 진행"이 헷갈림. 처방: 타이머 바에 경고색(잔여 적을 때 negative) 또는 별도 색 토큰.

### 4. 시니어 재산정 가중 총점

```
(정보3×3 + 터치4×3 + 시각4×2 + 인지3×3 + 피드백3×2) / 13
= (9 + 12 + 8 + 9 + 6) / 13
= 44 / 13
= 3.38
```

| | draft | **시니어** |
|---|:---:|:---:|
| 가중 총점(분모13) | 4.06 | **3.38** |
| 판정(합격선 3.5) | PASS | **FAIL (개선 권장)** |

→ 시니어 기준 **3.38 / 5.0, 일반 합격선 3.5 미달 → 조건부 FAIL(개선 권장 구간 3.0~3.5)**. 자동 FAIL은 아니나, "출시 가능"으로 통과시키긴 이르다. M1·M2·M3 해결 시 즉시 3.5 상회 가능.

### 5. 개선 제안 실용성 평가

- draft 의 10:10 가이드는 **대체로 한 줄 한 액션으로 실행가능**(토글 44px, 보더 1px 통일, 그룹 여백 2배 등) — 실용성 양호.
- 다만 일부가 **"C# 조건부 노출"**(HP/MP 전투 중에만)처럼 USS 한 줄로 안 끝나는 작업을 "10:10"에 올려 5분 액션의 결이 흐려짐. 이건 P2 코드작업으로 분리하는 게 정확.
- 가장 큰 약점: **M1(무게중심)·M2(포커스 충돌)** 같은 레이아웃 재배치 제안이 draft 에 아예 없어, "픽셀은 고쳐지나 화면이 안 고쳐지는" 리포트가 됨. 개선 가이드에 레이아웃 항목 1개는 필수.

### 6. "지금 5분 안에 고칠 1개" — 시니어 버전

draft 의 "토글 44px"도 맞지만 그건 **국소 터치 이슈**다. 시니어가 먼저 고칠 것은 **중앙 세로축 2포커스 충돌(M2) 해소** — `lh-boss-alert`(uss:841)를 화면 중앙이 아니라 **상단 1/3(스테이지 정보 바로 아래)** 로 내려, "보스 출현"과 "보상 받기"가 같은 세로 컬럼에서 시선을 양분하지 않게 한다.

> 단, 5분 USS 한 줄 수정이라는 제약을 엄격히 보면 토글 44px 가 더 안전한 5분짜리다. **5분=토글44px(국소), 다음 1순위=보스경고 위치 분리(동선)** 로 2단 권고.
