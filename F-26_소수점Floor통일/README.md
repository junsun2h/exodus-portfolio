# F-26. 클라-서버 소수점 Floor 전면 통일

> **코드 발췌 없음.** 이 항목은 전역 정책 변경·조사·설계 문서 형태의 작업이라
> 특정 파일로 잘라낼 수 없다. 아래 카드의 *근거* 항목이 실제 산출물이다.

**구간** Phase 2 (2026.02.26) | **포지션** 서버·TD | **AI** 협업

- **문제**: 클라(C#)와 서버(TS)가 같은 계산을 하는데 **반올림 정책이 달랐다.** 소수점 처리 하나가 다르면 데미지가 1 차이 나고, 그 1이 몬스터 처치 여부를 가르고, 결국 클라 예측(F-07)과 서버 결과가 어긋난다. **정확히 재현되지 않으면 결정론 설계 전체가 무의미해진다.**
- **해결**: 전 영역의 소수점 처리를 **`Floor`로 전면 통일**했다. 반올림·올림·버림이 혼재하던 상태를 하나로 고정한다. 어느 쪽이 "더 정확한가"보다 **양쪽이 같은가**가 중요하다는 판단.
- **기술**: 부동소수점 반올림 정책 통일, 클라-서버 계산 경로 전수 정리
- **정량**: 전 계산 영역 일괄 적용
- **근거**: `Docs/배틀/완료플랜/26.02.26_클라이언트-서버-소수점-반올림-Floor-통일-작업-계획서.md`
- **면접 포인트**: **Phase 3 동등성 골든 테스트(F-35)의 전제 조건.** 반올림 정책이 통일되지 않은 상태에서는 "C#과 TS 결과를 비트 단위로 대조한다"는 테스트가 성립할 수 없다. 즉 이 작업은 그 자체로는 지루하지만, **6주 뒤 자동 검증 체계를 가능하게 만든 준비 작업**이다. 정확성보다 일관성을 택한 판단이 요점.
- **슬라이드 자료**: 타임라인 상 마커 (F-35와 연결선으로 표시)
