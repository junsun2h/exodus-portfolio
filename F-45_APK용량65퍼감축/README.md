# F-45. Android 빌드 복구 + APK 65% 감축

> **코드 발췌 없음.** 이 항목은 전역 정책 변경·조사·설계 문서 형태의 작업이라
> 특정 파일로 잘라낼 수 없다. 아래 카드의 *근거* 항목이 실제 산출물이다.

**구간** Phase 3 (2026.07.28) | **포지션** 클라·TD | **AI** 협업

- **문제**: 개발용 Android 빌드가 나오지 않는 상태였고, 빌드에 성공해도 APK가 **708.6MB**였다. 모바일 게임으로 배포 불가능한 크기다.
- **해결**: 빌드 복구와 용량 감축을 함께 처리해 **708.6MB → 248.2MB (-65%)**를 달성했다.
  - **미참조 VFX 797MB 정리** — Unity의 `Resources/` 폴더는 **참조 여부와 무관하게 전량 빌드에 포함**된다. 이 특성을 역이용해, `Resources/` 안의 실제 미참조 VFX 자산을 찾아 정리했다. "쓰지 않는데 들어가 있는 것"이 용량의 대부분이었다.
  - **EDM4U 문제 규명** — External Dependency Manager가 Exclusions 블록을 재생성할 때 **namespace 줄을 삭제**하는 문제를 찾아냈다. 빌드가 깨지는데 원인이 툴의 자동 생성 동작에 있어 추적이 어려운 부류다.
  - **USS GUID 대조 사각지대 규명** — USS 파일이 폰트를 `guid=0000...` 형태의 **경로 참조**로 쓰고 있어, GUID 대조 방식의 미참조 자산 탐지에 잡히지 않았다. 이 때문에 실제로는 쓰이는 폰트 3종이 미참조로 분류될 뻔했고, 이를 발견해 복구했다.
- **기술**: Unity `Resources/` 빌드 포함 규칙, Addressables 자산 분류, EDM4U 동작 분석, GUID 기반 참조 추적 + 그 한계 보완, APK 빌드 파이프라인
- **정량**: **708.6MB → 248.2MB (-65%)** / 미참조 VFX **797MB** 정리 / 폰트 3종 오탐 복구

- **면접 포인트**: **-65%라는 수치보다 "자동 탐지의 사각지대를 찾아낸 것"이 기술적으로 더 중요하다.** GUID 대조로 미참조 자산을 찾는 방식은 표준적이지만, USS가 경로 참조를 쓰면 그 방식으로는 안 잡힌다. 이걸 모르고 진행했으면 **실제로 쓰는 폰트 3종을 지워서 출시 빌드가 깨졌을 것이다.** 자동화 도구를 쓰되 그 도구의 한계를 검증하는 태도가 요점. EDM4U의 namespace 삭제 건도 같은 부류 — 툴이 조용히 하는 일을 추적했다.
