# Clarifying Questions — 예시 모음

skill.md 본문에서 분리한 구체 예시/다이어그램. 질문을 작성할 때 형태가 헷갈리면 참조.

## 좋은 질문의 형태

### 1. 객관식 우선
열린 질문보다 옵션 제시:

❌ "어떻게 처리할까요?"
✅ "두 가지 방향이 있습니다. (A) 캡처 자동화 / (B) 수동 캡처 + 정적 분석. 작업량은 A=하루+, B=2시간. 어느 쪽?"

### 2. 1~3개로 제한
초과하면 사용자가 피곤해함. 가장 결정적인 분기 1~2개만.

### 3. 가정을 명시
"제가 이렇게 해석했는데 맞나요?" 형식.

✅ "장비 화면 폴리싱 = 색감/여백 등 시각만 손보고 레이아웃/인터랙션은 건드리지 않는다, 로 이해했습니다. 맞나요?"

### 4. 영향 범위를 같이 묻기
"어디까지 만질지"를 미리 합의 → 스코프 부풀림 방지.

✅ "이 변경이 PXButton만인지, BasePXButton 부모까지인지?"

### 5. 검증 기준 묻기
종료 조건을 미리 못박기.

✅ "끝났다는 걸 어떻게 확인하면 되나요? 컴파일 통과? 특정 화면 시각 확인? 회귀 평가?"

## 안티패턴 (이렇게 묻지 마라)

- ❌ "어떤 형식으로 보여드릴까요?" — 자명한 작업에 노이즈
- ❌ "정말 진행해도 될까요?" — 확인이지 명세 질문이 아님 (메모리: 묻지 말고 바로 진행)
- ❌ 5개 이상 한꺼번에 질문 — 사용자 압도
- ❌ "더 자세한 요구사항을 주세요" — 게으름. 구체적 객관식으로 나눠라
- ❌ 명백한 정답이 있는 질문 — 직접 결정하고 명시하라

## 워크플로우

```
사용자 요청 도착
    ↓
트리거 체크 (위 체크리스트)
    ↓
질문 필요? ─── No → 즉시 실행
    ↓ Yes
1~3개 질문 (객관식 + 가정 명시)
    ↓
사용자 답변
    ↓
"이 명세로 진행하겠습니다: ..." 한 줄로 합의 재확인
    ↓
실행
```
