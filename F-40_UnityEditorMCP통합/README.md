# F-40. Unity Editor MCP 통합

> **코드 발췌 없음.** 이 항목은 전역 정책 변경·조사·설계 문서 형태의 작업이라
> 특정 파일로 잘라낼 수 없다. 아래 카드의 *근거* 항목이 실제 산출물이다.

**구간** Phase 3 (2026.04.14) | **포지션** TD·툴 | **AI** 협업

- **문제**: AI가 Unity 프로젝트를 **읽을 수는 있어도 실행 상태를 볼 수 없다.** 런타임에 풀에 오브젝트가 몇 개 있는지, 딕셔너리 크기가 얼마인지는 코드만 봐서는 알 수 없고, 성능 최적화 검증에는 그 값이 필요하다.
- **해결**: **MCP(Model Context Protocol)로 Unity Editor를 AI에 연결**했다.
  - 도입 전 **UniCli와 CoplayDev/unity-mcp를 비교 조사**하고 선택했다(`Unity-CLI-MCP-도구-비교-조사.md`).
  - `execute_code`로 에디터 내에서 임의 C#을 실행할 수 있어, **런타임 풀 카운트·딕셔너리 크기를 직접 덤프**했다.
  - **실제로 성능 최적화 검증에 사용했다.** F-46의 몬스터 스폰 최적화에서 "이 딕셔너리가 정말 347개 엔트리를 만드는가"를 런타임 덤프로 확인했다.
- **기술**: MCP 프로토콜, HTTP 로컬 트랜스포트, Unity Editor 내 Roslyn C# 실행, 배치 실행
- **정량**: 도구 비교 조사 + 도입 명세서 / MCP 4종 중 하나로 상시 운영
