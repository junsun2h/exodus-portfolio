# F-36. 확률/경제 로직 사전 검증

> 소스 발췌: `src/` — 3개 파일

**구간** Phase 3 (2026.04.07 ~ 04.12) | **포지션** 서버 | **AI** 협업

- **문제**: 장비 강화 확률 로직(`roll_reinforce()`)에서 **float-snap 버그**를 발견했다. 부동소수점 처리 때문에 의도한 확률과 실제 확률이 어긋나는 부류로, **테스트를 돌려도 난수라서 잡히지 않는다.**
- **해결**: 확률 로직을 검증 가능한 대상으로 만들었다.
  - **`MockPRNG` 결정론 주입** — 난수원을 주입 가능하게 만들어, 테스트에서 원하는 값을 고정한다. 확률 로직을 **결정론적으로 테스트**할 수 있게 된다.
  - **확률 불변조건 검증** — 확률 합 = 1.0, 각 값이 범위 [0,1] 안에 있는가. 개별 케이스가 아니라 **성립해야 하는 속성**을 검사한다.
  - 관련 위키(`위키_장비강화_연속실패보정(Pity)`)로 규칙을 문서화.
- **기술**: PRNG 의존성 주입, 결정론 테스트, 불변조건(invariant) 검증, 부동소수점 경계 처리
- **정량**: float-snap 버그 수정 명세서 1종 + 불변조건 검증 도입

- **면접 포인트**: **"난수를 쓰는 코드를 어떻게 테스트하는가"**에 대한 표준 해법(PRNG 주입)을 실제 버그를 계기로 도입한 사례. 더 중요한 것은 **불변조건 검증**으로 넘어간 것 — 개별 케이스 테스트는 통과하는 확률 버그도 "합이 1.0인가"는 통과하지 못한다. 이 접근이 다음 날 F-37의 전수 감사로 이어져 **51개 결함**을 찾아낸다.
